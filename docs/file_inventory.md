# File Inventory — Brief descriptions

Top-level

- `config.yaml` — centralized path configuration file for `master_template_path` and multi-client definitions (`clients:`).
- `Jenkinsfile` — CI pipeline used by Jenkins to checkout, prepare secrets, and run `ansible-playbook` on an agent.
- `playbook.yaml` — main Ansible playbook that orchestrates migration, rendering, and copy-back to Windows targets.
- `requirements.txt` — Python dependencies for local testing and `xml_migration.py` (`lxml`, `PyYAML`, `sentence-transformers`).
- `PROJECT_DOCUMENTATION.md` — high-level, beginner-friendly documentation (index into `docs/`).
- `README.md` — project summary and quick notes (short).

Directories

- `files/` — organized XML folder containing subfolders:
  - `files/client_sources/` — client source XML files containing canonical values (`client1_source.xml`, `client2_source.xml`, `origin_source.xml`).
  - `files/master_templates/` — master XML template files containing `#{...}` placeholders (`master_config.xml`).
- `templates/` — generated Jinja2 templates produced by the migration process (e.g., `config.xml.j2`). This directory may be created by the pipeline.
- `final/` — generated final XML output files (e.g., `final/client1_config.xml`, `final/client2_config.xml`) for distribution to targets.
- `utils/` — helper scripts:
  - `config.py` — centralized configuration loader supporting `config.yaml` and environment variables.
  - `xml_migration.py` — core migration logic (parsing, matching, and writing `vars.yaml` and template).
  - `xml_migration_v0.py` — older variant (kept for reference).
  - `debug_match.py`, `debug_parser.py` — development/debug utilities supporting mapping logic.
- `tests/` — unit tests for `xml_migration.py` and support scripts (run with `python -m unittest`).

Other files

- `mapping_report.txt` — human-readable report of placeholder→value matches generated by the migration script.
- `mapping_ai_review.txt` — optional AI-suggested candidate mappings (requires `sentence-transformers`).
- `vars_client1.yaml`, `vars_client2.yaml` — the client-specific YAML variable files created by the migration script.

Notes

- Generated files (`templates/*`, `final/*`, `vars.yaml`, reports) should be ignored or treated as ephemeral in CI; consider adding them to `.gitignore` if you don't want to commit generated artifacts.
- If you need a complete tree listing, run `git ls-files` or `ls -R` from the repo root and I can create a full annotated list.
